    Answers from your data without waiting for an analyst

    Most business questions already have an answer sitting in a database. Getting it usually means filing a request and waiting for someone who writes SQL. This tool lets anyone ask in plain English and shows its working, so the answer can be checked instead of taken on faith.

    The problem

    Managers ask simple questions like "which region sold the most last quarter?" Each one costs an analyst ten minutes and the manager a day of waiting. Dashboards cover the questions someone predicted. The rest wait in a queue, and some never get asked.

    What it does for you

    • Answers a question in a sentence. Simple questions take a couple of seconds; on this demo's free model tier, harder ones can take up to a minute.
    • Shows the exact query it ran and the rows behind the answer, so a numbers person can verify it.
    • Asks you to clarify instead of guessing when a question is ambiguous.
    • Can only read. It cannot change, delete or add data.

    How it works

    The data in this demo

    A small, made-up shop: customers, products, orders and order lines, with a few realistic traps. Only shipped orders count toward revenue, some details sit in a JSON field, and the price a customer paid differs from today's list price. Everything is synthetic, so nothing private is ever sent to the AI model. You can browse every row from the Playground.

    Honest limitations

    • The demo database is tiny. Real schemas with hundreds of tables need table descriptions and business definitions loaded in. The system supports this, but it isn't shown here.
    • The evaluation is 15 questions on one schema. It shows the method works; it doesn't prove accuracy on your data. We'd build a question set from your own reports before go-live.
    • The score above belongs to the default model. The other model in Settings is offered for comparison but hasn't been scored.
    • The free model tier caps how many questions it can answer per minute and per day, so the public demo can slow down or pause. When one model runs out, switch to the other in Settings.
    • An answer can still be wrong. That's why the query and rows are always shown next to it.

    Running it on your own data

    • A read-only database login. It works with SQLite and PostgreSQL today; others need a small adapter.
    • A short list of business definitions, such as what counts as "revenue" or an "active customer".
    • Twenty or so real questions with known answers, so we can measure accuracy on your schema before anyone relies on it.
    • A model endpoint you approve. It can be a hosted model, or one inside your own cloud so data never leaves it.

    Tech stack

    Python standard library only on the server: an agent loop with tool calls, a read-only SQLite or PostgreSQL layer that checks every statement before it runs, and a result-matching evaluator. The model is any OpenAI-compatible endpoint; this demo uses gpt-oss on Groq. The page is plain HTML, CSS and JavaScript, hosted on Vercel.

    Demo data is synthetic. Questions you type are sent to the AI model provider to generate SQL; don't enter personal information.
